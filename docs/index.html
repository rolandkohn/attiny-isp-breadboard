Arduino Nano as ISP · Breadboard

Flash an ATtiny84A on a breadboard

Nano and ATtiny sit in the same half-size breadboard (30 columns). No loose cables to the Arduino, just short jumpers, plus R1, C1 and the reset capacitor right next to the Nano. Once built, the breadboard stays a permanent programmer.

Layout

Check your power rails first. On the breadboard used here both rail pairs run − on top, + below (top: − outer, + inner; bottom: − inner, + outer). Many breadboards are labelled the other way round. Go by the red/blue lines on your board and mirror the 5V/GND jumpers if needed, otherwise 5V lands on GND. Also check whether long breadboards have the rails split in the middle.

Top view, Nano with USB to the left and components facing up. Holes are named row a–j plus column 1–30, e.g. b23. Row j is at the top, a at the bottom. Hover a hole to see its name. Click a signal to highlight its jumper.

Steps

  1. Prepare the Nano once, outside the breadboard, USB only: upload File → Examples → 11.ArduinoISP → ArduinoISP. Clones with a CH340 usually need processor ATmega328P (Old Bootloader), otherwise the upload fails. The sketch stays on the Nano until you upload something else.
  2. Populate the breadboard: ATtiny, the jumpers from the table, R1, C1 and electrolytic C2 (long leg + in b13, stripe − in b14). C2 stays in.
  3. Plug in the Nano and connect USB. From now on the breadboard is a dedicated programmer.
  4. Flash the ATtiny with ATTinyCore: board ATtiny24/44/84(a) (No bootloader), chip ATtiny84(a), clock 8 MHz (internal), programmer Arduino as ISP. For every new chip run Burn Bootloader once (sets the fuses), then Sketch → Upload Using Programmer.

If the Nano itself needs reflashing (e.g. ArduinoISP got overwritten and you only get not in sync): pull the Nano out of the breadboard and start again at step 1. It does not work with C2 in the circuit.

For all checks below: enable File → Preferences → Show verbose output during: upload. Otherwise the IDE hides the avrdude messages.

The pinout assumes a standard Nano. Compare with the labels on your board before plugging in: top D12 … D2, GND, RST, RX0, TX1; bottom D13, 3V3, REF, A0–A7, 5V, RST, GND, VIN.

Cheap Nano clones (CH340, Windows)

Most cheap Nanos use a CH340 USB chip. Two problems are common, both in step 1, before the breadboard is involved at all. Test with Blink first: if Blink uploads, ArduinoISP will too.

Installing the older driver (v3.4)

  1. Download Windows-CH340-Driver.zip from SparkFun's CH340 guide and unzip it. The WCH website only offers the newest version. Other signed versions are in the Microsoft Update Catalog (search wch.cn CH340).
  2. Device Manager → USB-SERIAL CH340 → Update driver → Browse my computer → Let me pick from a list → Have Disk… → select the .inf in the unzipped folder.
  3. Unplug, replug, upload Blink.

If Windows Update brings back 4.0 later: Device Manager → driver → Roll Back Driver → reason "My apps don't work with this driver". Windows then leaves the old driver alone.

3 · ATtiny: is the sketch on it and running?

Verify: after Sketch → Upload Using Programmer avrdude reads the flash back and compares. … bytes of flash verified without errors means the code is on the chip correctly.

Function test: plug in the test LED (drawn top right in the layout) and upload blink_pa3.

i24 (pin 10, PA3) ──[220–330 Ω]── i28
j28 ── LED anode (long leg)
LED cathode ── top − rail
void setup() { pinMode(PIN_PA3, OUTPUT); }
void loop() {
  digitalWrite(PIN_PA3, HIGH); delay(500);
  digitalWrite(PIN_PA3, LOW);  delay(500);
}
LEDMeaning
1 s per cycleSketch runs, fuses are correctly set to 8 MHz
8 s per cycleBurn Bootloader was skipped: the chip runs at the factory 1 MHz
darkSketch not running or LED reversed (long leg = anode = resistor side)

PA3 is not an ISP pin, so the LED can stay plugged in and does not disturb flashing. After the upload the Nano releases RESET, R1 pulls it high, and the ATtiny starts running right on the breadboard.
